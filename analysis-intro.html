صفحه اصلی مبانی نظری آزمایش نتیجه‌گیری

عنوان مقاله: تحلیل پیچیدگی زمانی و مقایسه عملکرد List و Set در پایتون

حوزه: تحلیل الگوریتم و ساختار داده

نوع مطالعه: بررسی نظری همراه با آزمایش تجربی

هدف: بررسی تأثیر انتخاب ساختار داده بر زمان جست‌وجو

۱. چکیده

انتخاب ساختار داده مناسب یکی از عوامل مؤثر بر کارایی نرم‌افزار است. در این مقاله، عملکرد عملیات بررسی وجود یک عنصر در دو ساختار داده list و set در زبان پایتون از نظر پیچیدگی زمانی و روش اندازه‌گیری تجربی بررسی می‌شود. همچنین محدودیت‌های مقایسه و عوامل مؤثر بر نتایج توضیح داده خواهند شد.

۲. مبانی نظری

۲.۱. ساختار List

لیست در پایتون یک مجموعه مرتب از عناصر است که امکان دسترسی به عناصر با اندیس را فراهم می‌کند. برای بررسی وجود یک مقدار، ممکن است لازم باشد عناصر به‌ترتیب بررسی شوند تا مقدار موردنظر پیدا شود یا لیست به پایان برسد.

پیچیدگی زمانی جست‌وجوی یک مقدار در لیست در بدترین حالت برابر O(n) است؛ در اینجا n تعداد عناصر لیست است.

۲.۲. ساختار Set

مجموعه set برای نگهداری عناصر یکتا طراحی شده و در پیاده‌سازی معمول پایتون از جدول درهم‌سازی استفاده می‌کند. بررسی عضویت در set به‌طور میانگین پیچیدگی O(1) دارد. با این حال، در بدترین حالت پیچیدگی می‌تواند O(n) شود.

ویژگی List Set
ترتیب عناصر حفظ می‌شود برای ترتیب‌دهی مناسب نیست
عناصر تکراری مجاز نگهداری نمی‌شوند
جست‌وجوی میانگین O(n) O(1)
حافظه معمولاً کمتر برای همین عناصر معمولاً بیشتر به دلیل ساختار درهم‌سازی

۳. پیاده‌سازی اولیه

در مثال زیر، وجود عدد ۷۵۰۰۰ در یک لیست بررسی می‌شود. 

numbers = list(range(100_000))

target = 75_000

found = target in numbers

print(found)

در این مثال، پایتون عناصر لیست را از ابتدا بررسی می‌کند تا به مقدار هدف برسد. چون مقدار هدف نزدیک انتهای لیست قرار دارد، تعداد زیادی از عناصر بررسی می‌شوند.

۴. پیاده‌سازی مبتنی بر Set

numbers = set(range(100_000))

target = 75_000

found = target in numbers

print(found)

در این نسخه، ساختار set برای بررسی عضویت استفاده شده است. بررسی عضویت در این ساختار به‌طور میانگین سریع‌تر است، اما ساخت خود set نیز زمان و حافظه مصرف می‌کند.

نکته علمی: اگر قرار است فقط یک بار جست‌وجو انجام شود، هزینه ساخت set ممکن است مزیت آن را کاهش دهد. اگر جست‌وجوهای زیادی روی داده‌های یکسان انجام شوند، استفاده از set می‌تواند سودمندتر باشد.

۵. طراحی آزمایش تجربی

برای مقایسه معتبر، باید اندازه داده، مقدار مورد جست‌وجو، تعداد تکرارها و هزینه ساخت ساختار داده مشخص باشند. کد زیر زمان جست‌وجو را جدا از زمان ساخت list و set اندازه‌گیری می‌کند. 

from timeit import repeat

sizes = [1_000, 10_000, 100_000]
repetitions = 5
number = 1_000

for size in sizes:
data_list = list(range(size))
data_set = set(data_list)
target = size - 1

list_times = repeat(
    stmt="target in data_list",
    globals=globals(),
    repeat=repetitions,
    number=number
)

set_times = repeat(
    stmt="target in data_set",
    globals=globals(),
    repeat=repetitions,
    number=number
)

list_best = min(list_times) / number
set_best = min(set_times) / number

print(f"Size: {size}")
print(f"List search: {list_best:.8f} seconds")
print(f"Set search:  {set_best:.8f} seconds")
print()
محدودیت آزمایش: این کد زمان جست‌وجو را اندازه می‌گیرد، نه هزینه ساخت ساختارها را. همچنین انتخاب آخرین عنصر باعث می‌شود جست‌وجوی لیست تقریباً تمام عناصر را بررسی کند. برای مطالعه کامل‌تر باید موقعیت‌های مختلف عنصر، داده‌های تصادفی و هزینه ساخت set نیز بررسی شوند.

۶. تحلیل نتایج

پیش از اجرای آزمایش، انتظار نظری این است که با افزایش اندازه لیست، زمان جست‌وجو به‌طور تقریبی متناسب با تعداد عناصر افزایش یابد. در مقابل، زمان جست‌وجو در set در حالت میانگین معمولاً رشد بسیار کمتری خواهد داشت.

این پیش‌بینی جایگزین داده‌های واقعی نیست. برای نتیجه‌گیری علمی باید خروجی اجرای آزمایش ثبت شود و شرایط محیط اجرا، نسخه پایتون و تعداد تکرارها نیز گزارش شوند.

۷. نتیجه‌گیری

انتخاب میان list و set به نوع مسئله بستگی دارد. لیست برای حفظ ترتیب، نگهداری مقادیر تکراری و دسترسی اندیسی مناسب است؛ درحالی‌که set برای بررسی مکرر عضویت در میانگین شرایط کارایی بالایی دارد.

بهینه‌سازی معتبر فقط انتخاب ساختاری با پیچیدگی نظری بهتر نیست؛ هزینه ساخت، مصرف حافظه، ویژگی‌های داده و نتایج اندازه‌گیری واقعی نیز باید در تصمیم نهایی لحاظ شوند.
